# VWKanban design

The condensed, current version of the MVP plan. It is the source of truth for behaviour.
Section numbers match the original plan, so a code comment that says `plan §3.2` means
§3.2 here. When behaviour changes, update the section here in the same PR, and add a
line to §11.

## §0 Decisions

| Topic | Decision |
|---|---|
| Goal | Fast, vim-style, open-source web kanban; one `docker compose up`; teams edit the same board live (hackathons); CSV in and out |
| DB | PostgreSQL 17, tuned small (`shared_buffers=64MB`, `max_connections=20`, `mem_limit 256m`) |
| Frontend | Svelte 5 + Vite + TS SPA behind nginx. CodeMirror 6 + `@replit/codemirror-vim` for card fields only, lazy-loaded. Prompts (board, column and member names) are plain inputs |
| Sync | REST for load, dashboard, auth, CSV and members. Every board mutation is an op: WS, or `POST /ops`, which runs the same handler. A per-board `seq` is the order of truth, and clients apply events strictly in seq order |
| Conflicts | Moves and `is_done`: last write wins. Text fields (`title`, `description`, `tags`, `date`): field-level check against a `base_seq` frozen at field entry; a stale write is rejected and the draft is kept. Undo uses the same check |
| Ordering | Fractional-index string keys, computed only by the server from `after_id`/`before_id` |
| Children | Depth 1. Shown inside the parent's card view; the tile shows `n/m` |
| Tags | `text[]` on the card; colour = hash(name) → 8-colour palette |
| `date` | User-edited due date with an optional wall-clock time, `YYYY-MM-DD[ HH:MM]`, no timezone (`created_at`/`updated_at` are separate) |
| Statuses | `statuses` table per board; new boards get Todo / Doing / Done |
| Members | `board_members` with roles `owner`, `editor` |
| Users | First admin from `.env`; `vwk user` CLI; `ALLOW_SIGNUP` flag (off by default) |
| Auth | argon2id in a thread pool; server sessions in an HttpOnly `SameSite=Lax` cookie with `Secure` from `PUBLIC_URL`'s scheme; Origin check for CSRF and on the WS handshake; OAuth-ready schema |
| TLS | Plain HTTP by default; README shows Caddy in front |
| Workers | One uvicorn worker; in-memory fan-out per board |
| Images | CI publishes `ghcr.io/viadavyd/vwkanban-{app,web}`; compose pulls them, with `build:` as a fallback |
| License | MIT |

## §1 Architecture

```
browser (Svelte SPA; CodeMirror vim lazy-loaded for card fields)
  │  /            static files
  │  /api/*       REST
  │  /api/boards/{id}/ws   WebSocket (ops + events)
  ▼
web: nginx 1.27 (SPA, reverse proxy, WS upgrade, login/signup limit 5 r/min per IP, 6 MB body cap)
  ▼
app: FastAPI on uvicorn, 1 worker
  auth    sessions, argon2 (thread pool), signup flag
  boards  REST CRUD, dashboard summary, members
  sync    apply_op: board lock → txn{seq++, checks, mutate, board_events} → commit → broadcast
  hub     in-memory {board_id: sockets} + presence
  csvio   export / import (one txn, then a board.import event)
  ▼
db: PostgreSQL 17
```

## §2 Data model

PKs are UUIDv7. Card and status ids are generated by the client, so optimistic creates
need no id remap.

- `users(id, username citext UNIQUE [a-z0-9_.-]{3,32}, password_hash NULL, created_at)`
- `sessions(id = sha256(cookie token), user_id, created_at, expires_at)`: 30 days, sliding
- `boards(id, title 1..120, created_by, created_at, updated_at, seq, next_number)`: seq
  and numbers are advanced in one `UPDATE … RETURNING` under the row lock
- `board_members(board_id, user_id, role owner|editor)`
- `statuses(id, board_id, name 1..40 UNIQUE per board, color, position, field_meta)`. The
  palette is red, yellow, blue, green, purple, orange, pink, gray
- `cards(id, board_id, number UNIQUE per board, parent_card_id, status_id RESTRICT, position,
  title 1..300, description ≤20 000, is_done, tags text[] (each 1..30, no ';', ≤50, distinct),
  date, due_time, field_meta, created_by, created_at, updated_at, deleted_at)`. `date` +
  `due_time` are one field on the wire (`date`, see `boards/due.py`); `due_time` needs a date. CHECK: a child has no
  status, and a top-level card has one. Depth 1 is enforced in `apply_op`
- `board_events(board_id, seq, op_id UNIQUE, client_id, actor_id, kind, payload, created_at)`:
  the op log for replay and idempotency. It keeps the last 10 000 events per board,
  trimmed on startup
- `field_meta` (on cards and statuses): `{field: {seq, client}}`, the seq and tab that last
  wrote each field. Conflict and undo checks read it, never the event log
- `position` columns use `COLLATE "C"`
- Soft delete: `deleted_at`. Children cascade
- **Status delete rule:** refused while the column has live cards. Its soft-deleted cards
  are purged in the same transaction, and undoing their deletion then gets `gone`
- **CSV mapping:** `id`→`number`, `title`, `status`→status name, `date` YYYY-MM-DD[ HH:MM],
  `parent`→parent's number, `is_done`, `tags` joined with `;`, `description`

## §3 API

All routes are under `/api` and use JSON. Errors are `{error:{code,message}}` with codes
`unauthenticated forbidden not_found validation conflict gone`. Every state-changing
request needs an `Origin` equal to `PUBLIC_URL`'s.

### §3.1 REST

| Route | Purpose | Access |
|---|---|---|
| `GET /auth/config` | `{signup_enabled}` | public |
| `POST /auth/login` · `POST /auth/signup` (404 unless `ALLOW_SIGNUP`) | sets `vwk_session` | public, rate-limited |
| `POST /auth/logout` | deletes the session and closes its sockets (4401) | user |
| `GET /auth/me` | `{id, username}` | user |
| `GET /boards` | dashboard tiles with summary counts (one GROUP BY) | member |
| `POST /boards` · `PATCH /boards/{id}` · `DELETE /boards/{id}` (closes its sockets, 4404) | create (seeds 3 columns and owner membership) / rename / hard delete | user / owner / owner |
| `GET /boards/{id}` | `{board, seq, statuses, cards (with children), members}` | member |
| `POST /boards/{id}/ops` `{client_id, op}` | the same as a WS op; returns ack or reject | member |
| `GET/POST/DELETE /boards/{id}/members[/{user_id}]` | adding a username makes them an editor (an unknown name gets 404); the owner can't be removed; removal closes their sockets (4403); no board event | list: member; change: owner |
| `GET /boards/{id}/export.csv` | download | member |
| `POST /boards/{id}/import[?dry_run=1]` | raw `text/csv` body, ≤5 MB (413), ≤5 000 rows; returns `{created, statuses_created, numbers, warnings}` | member |
| `GET /healthz` | liveness + DB ping | public |

### §3.2 WebSocket `/api/boards/{id}/ws`

**Handshake:** checks Origin (4400), then the session (4401), the board (4404) and
membership (4403), all before anything is registered. A refused handshake is `accept()`
followed by an immediate `close(code)`. Messages are capped at 128 KB. More than 50 ops/s
on one socket closes it with 4429.

- **Client → server:** `hello{client_id, last_seq}` (the loaded board's seq; 0 = no replay) ·
  `op{op_id, kind, base_seq, undo?, data}` · `ping` (every 25 s)
- **Server → client:** `welcome{seq, presence}`, then the replayed `event`s or `resync`.
  Replay happens if `last_seq ≥ oldest retained − 1`, else resync; `last_seq > seq` also
  means resync.
  Other messages:
  - `event{seq, op_id, client_id, actor, kind, data}`: data is the final server state,
    including position, number and field_meta
  - `ack{op_id, seq}`
  - `reject{op_id, code, message, current}`
  - `presence{users}`
  - `resync`
  - `pong`

**`base_seq`:**
- For a text field, it is the confirmed seq when the user entered the field. It stays
  frozen and moves only on the user's own ack for that field.
- For undo, it is the seq of the op being undone.
- For other ops, it is informational only.

| kind | data | rule |
|---|---|---|
| `card.create` | `id, status_id \| parent_id, after_id?, before_id?, title, description?, tags?, date?, is_done?, children?[]` (no children on a child) | target must be live, else `gone` |
| `card.update` | `id, fields{title?, description?, tags?, date?, is_done?}` | text fields get `conflict` if `field_meta[f].seq > base_seq` and it was written by another client; `is_done` is LWW |
| `card.move` | `id, status_id \| parent_id, after_id?, before_id?` | LWW; card and target must be live |
| `card.delete` / `card.restore` | `id` (delete is soft and cascades; restore is undo only) | LWW / undo check |
| `status.create` | `id, name, color, after_id?, before_id?` | duplicate name → `validation` |
| `status.update` / `status.move` | `id, name?, color?` / `id, after_id?, before_id?` | LWW |
| `status.delete` | `id` | `validation` if the column has live cards |
| `board.import` | server-only event | clients resync; not undoable |

**Undo** (`undo: true`) is rejected with `conflict` if another client wrote any field
the inverse touches after `base_seq`. A `gone` message names who did it: "#5 was deleted
by bob".

### §3.3 Apply pipeline (`sync/ops.py::apply_op`)

1. Take the per-board `asyncio.Lock`.
2. If the `op_id` was already applied, resend the stored ack.
3. Start a transaction and check membership and that every referenced entity is on this
   board and live.
4. `UPDATE boards SET seq=seq+1 …`.
5. Run the conflict checks against `field_meta`. A reject rolls back and consumes no seq.
6. Mutate, and write `field_meta[f] = {seq, client}` for every field written. Positions
   come from `key_between` of the live neighbours; with no live neighbour the card goes
   to the end.
7. Insert the `board_events` row, commit, ack, then broadcast through the hub (outbound
   queues, never awaited under the lock).

### §3.4 Client sync model (`lib/sync/store.ts`)

- **State:** the confirmed state plus pending ops; the view is confirmed with pending
  applied on top.
- **Event order:** events apply in seq order. A gap waits 1 s, then the client resyncs.
- **Own and other events:** your own event drops the matching pending op. Another
  client's event applies to confirmed, then pending is re-applied.
- **A field being edited** is never touched by a remote event. The field shows
  `remote changed — :w! keep mine · :e! take theirs`. Saving without `!` gets a conflict.
  `:w!` resends with the current seq, and `:e!` takes the remote value.
- **Reject:** drop the op, apply `current`, and show a toast.
- **Reconnect:** backoff from 0.5 to 8 s, then `hello{last_seq}`, then re-send pending ops
  with their original `op_id`. Ops queue in memory while offline. The top bar shows
  `● live` / `◌ reconnecting` / `○ offline`.

### §3.5 Concurrency cases (each is a multi-client test in `tests/ws/`)

- A and B move the same card: applied in seq order, last wins, both converge.
- A and B insert after the same card: they get distinct keys and the same order everywhere.
- A and B edit different fields of one card: both apply.
- A and B edit the same text field: the first save wins. The second gets `conflict`,
  keeps the draft, then chooses `:w!` or `:e!`.
- The editor's `base_seq` stays frozen even after remote events, so a stale save is a
  conflict. This holds even after the log was trimmed, because the check uses field_meta.
- `:w` twice by the same client is no self-conflict.
- Moving, pasting or adding a child under a card someone deleted gets `gone`. The register
  or the typed title is kept.
- A card deleted while A edits it: a banner shows, and on close the draft goes to A's
  register (`p` recreates it).
- A move into a column while another client deletes that column: the first commit wins.
- Inserting after a card someone moved away: the server uses `before_id`, or the end of
  the column.
- Undo after someone else changed the card: `conflict`, "can't undo: changed by B".
- Offline ops are re-sent after the replay. A duplicate send gets the same ack.

### §3.6 CSV rules (`csvio/`)

- **Headers:** `id,title,status,date,parent,is_done,tags,description` on export. On import
  they match case-insensitively, in any order. Only `title` is required, and unknown
  headers are ignored with a warning.
- **Append only:** import never changes existing cards.
- **Numbers:** CSV ids become card numbers as-is only if the board has never had a card
  and every id is a positive integer. Otherwise every row is renumbered, and `parent`
  follows the remap. Duplicate ids are an error.
- **Parents:** a missing parent makes the row top-level, with a warning. A parent that is
  itself a child, or a self-parent, is a depth error.
- **Status:** matched case-insensitively. An unknown name creates a column on the right,
  with the next palette colour. An empty status goes to the first column, and a board with
  no columns gets `Todo`. Children ignore status.
- **Field formats:**
  - `is_done`: `true false 1 0 yes no`
  - `date`: `YYYY-MM-DD`, `YYYY-MM-DD HH:MM` (a `T` separator is accepted) or empty
  - `tags`: split on `;`, trimmed, deduped
  - encoding: UTF-8, BOM tolerated
- **All or nothing:** one bad row rolls back the whole import. Errors list row numbers,
  counting the header as row 1. A successful import uses one seq and emits one
  `board.import` event. `dry_run` runs the same validation and rolls back.
- **Export order:** columns by position, cards by position, each card's children right
  after it.
- **Formula escape:** export prefixes `'` to any text cell starting with `= + - @`, Tab,
  CR or `'`, and import strips one. Round-trip is byte-identical.

## §4 Frontend

### §4.2 Modes

```
DASHBOARD --Enter--> BOARD --i / a / A--> CARD --i / a--> FIELD (vim)
    ^                  |  ^                 |  ^                |
    +-----Esc/Ctrl+C---+  +---Esc/Ctrl+C----+  +---Esc/Ctrl+C----+ (plain vim NORMAL only)
Overlays (help, confirm, prompt, members) stack on any mode; Esc closes them first.
BOARD has pending state (x mark, `s` prefix): Esc clears it before going back to DASHBOARD.
```

- **Key handling:** one capture-phase `keydown` listener (`lib/keys/dispatch.ts`)
  dispatches on (top mode, key) from `keymap.ts`. Screens bind keys by `pushMode()`.
- **FIELD mode:** only Esc and Ctrl+C are bound. Each leaves the field only from plain
  NORMAL: no insert or visual mode, and no pending operator, count or register. Otherwise
  the key goes to vim. That makes it one level per press.
- **Leaving a field saves it.** `:w` saves and stays, and an invalid value stays in the
  field with the reason shown.
- **Unsaved drafts go to the register** when the card closes. That covers an unresolved
  conflict, an invalid value, or a remote delete. Text is never lost.
- **New card** (`a`/`A`): a placeholder opens with its title in INSERT. If the title is
  still empty when the card closes, nothing is sent.

### §4.3 Keymap

The complete, current keymap is `frontend/src/lib/keys/keymap.ts`, and the help overlay
(`?`) renders from it. A summary:

- **Dashboard:**
  - `h j k l`: move the selection
  - `Enter`: open the board
  - `a` / `r` / `d`: create / rename / delete a board
  - `Q`: log out
  - `?`: help
- **Board:**
  - `h l` move between columns, `j k` between cards
  - `i`: open the card
  - `a` / `A`: new card below / above
  - `y`: copy with children
  - `p`: paste a copy, or move the x-marked card here
  - `d`: delete (the deleted card goes to the register)
  - `x`: mark the card to move
  - `Space`: toggle done
  - `u`: undo (a stack of 50)
  - `s a` / `s r` / `s c` / `s d`: add / rename / recolour / delete a column
  - `H L`: move a column
  - `M`: members
  - `E` / `I`: CSV export / import
  - `Esc`: clear pending, then go to the dashboard
- **Card:**
  - `j k`: move between fields (title → tags → date → description → children →
    `[add child]`)
  - `i` / `a`: edit in NORMAL / INSERT
  - `o O`: add a child below / above
  - `Space`: toggle done (this card, or the child on that row)
  - `d`: delete a child
  - `u`: undo the last op on this card
- **Field:** full vim, plus `:w`, `:w!` and `:e!`. Title and tags are single-line (`Enter`
  saves).
- **Register:** one in-app register per tab, holding a JSON card snapshot. The system
  clipboard is not used.

### §4.4 Screens

- **Login:**
  - a centred panel with username, password and `Enter` to submit
  - a signup link, shown only when signup is enabled
- **Dashboard:**
  - a wrapping grid of tiles: title, `12 cards · 4 done`, the per-column counts and
    `updated 3 min ago`
  - empty state: "press `a` to create a board"
- **Board:**
  - **Top bar:** `VWKanban / title`, the mode indicator (`-- BOARD --`, vim mode, `x: #12`,
    `s…`), the presence initials, the sync dot and the username.
  - **Columns:** a header boxed in the status colour.
  - **Card tile:** the title, a meta line `#12 · due 11-30 · ☐ 2/3`, tag pills and a done
    checkbox.
  - **Card view:** a centred overlay with `#id ☐ title` / tags · date / description /
    children / `[add child]`.
- **Mouse:** optional. Click selects, double-click opens.

## §7 Non-functional targets (enforced by `make perf`, report-only in CI)

- Keypress → paint: p95 < 50 ms on a 500-card board with a 4× CPU throttle (`j k h l Space`).
- Remote change visible on another client: p95 < 300 ms with 20 ms netem; server apply
  p95 < 45 ms (raised from 30 ms, see §11).
- 500-card board: `GET` in < 150 ms, interactive in < 1 s, no long tasks > 50 ms when
  holding `j`.
- Initial JS < 80 KB gz; the editor chunk is lazy.
- Cold deploy on 1 GB: healthy in < 3 min including the image pull; login works over
  plain HTTP.
- Memory: idle < 300 MB; 20 clients on 500 cards < 600 MB. mem_limits: app 256m, db 256m,
  web 32m.

## §9 Known trade-offs

- **Single worker:** the per-board lock serializes ops. The next step is fan-out through
  `LISTEN/NOTIFY`.
- **Text conflicts** are a whole-field choice (`:w!` / `:e!`); there is no merge.
- **Behind a proxy**, the login rate limit needs `set_real_ip_from` (see the README).
- **Perf numbers on shared CI runners** are noisy, so they are report-only there.
